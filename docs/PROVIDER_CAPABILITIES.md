## 探测输出

`scripts/provider_probe.py`（待实现）对每项打印 `PASS / FAIL / N/A + evidence`，并更新“结果”和“环境”：

- 每项独立发送请求，一项失败不影响其他项；
- 输出带原始证据：`usage`、错误码、错误信息；
- 尽量减少真实请求，运行前列出将发出的 API 调用；
- `N/A` 表示端点不支持，`FAIL` 表示探测程序或使用方式失败。

## 降级方案

| 能力 | 不可用时的行为 |
|---|---|
| C1/C2/C3 | 不实现 `cache_control` 路径；上下文压缩只使用上下文与 token 预算，报告不包含缓存命中率 |
| C4/C5 | 降级到非流式 `generate()`；事件与渲染接口不变 |
| C6 | 上下文压缩仍把工具调用组视为原子整体；性质测试人工构造并行调用组 |
| C7/C8 | 即使端点接受这些输入，本地 `assert_history_valid()` 仍执行严格不变量 |
| C10 | 不往返传递推理块，并在限制中说明 |
| C12 | 根据探测结果把 `token_limit` 写入配置，不硬编码 `80000` |
