# ADR-0007：上下文使用两阶段派生视图，文件状态归入编辑引擎

- 日期：2026-08-24
- 状态：已采纳（未实现）
- 取代：ADR-0001 的 FileLedger 层；保留仅追加的原始日志、工具结果淘汰、单一摘要与安全边界
- 关联：`docs/specs/01-context-manager.md` · `docs/specs/04-transactional-edit.md`

## 背景

ADR-0001 把 FileLedger 作为上下文管理的第三层，但没有一个离线测试会在删除它后独立失败。与此同时，写前读取、读取后文件变化检查和写后哈希已经是编辑引擎必须拥有的状态。两个模块同时持有文件新旧状态会形成两个事实来源。

## 选项

1. FileLedger 继续作为上下文管理的第三层，每轮注入。
2. 文件状态只由编辑引擎持有；上下文管理器只做工具结果淘汰与单一摘要。
3. 完全不跟踪文件状态，依赖模型主动重新读取。

## 决定

选择选项 2。上下文管理器只管理消息视图；编辑引擎以磁盘为事实来源，记录 `(mtime_ns, size, sha256)` 并拒绝基于旧内容的补丁。只有可复现任务证明模型在压缩后缺少工作集状态，才另开 ADR 设计只读摘要。

## 为什么否决其他的

已有版本化文档存储、多个使用方需要工作集视图时，FileLedger 层合理；当前项目没有该基础。

只读 agent 可以不跟踪文件状态；coding agent 允许 bash 或外部进程修改文件，完全不检查读取后变化会覆盖新内容。

## 怎么验证

- 上下文不变量测试不需要文件系统测试样例；
- 编辑测试能独立证明外部修改会触发拒绝；
- 删除上下文管理器不会关闭编辑引擎的文件变化保护；
- 工作集摘要必须由当前方案的具体失败案例触发。
