# ADR-0005：FakeLLM 使用按请求路由的有序队列

- 日期：2026-08-24
- 状态：已采纳（未实现）
- 关联：`docs/specs/00-test-harness.md` · `docs/reference/agent-testing-survey.md`

## 背景

`Agent.run()` 每一步发送主模型请求，但 `_summarize_messages()` 还会在 `agent.py:275-283` 发送 `tools=None` 的循环外摘要请求。单个 FIFO 会在压缩触发时错位。外部源码调研也显示 gemini-cli 为不确定的后台任务增加了非严格路由。

## 选项

1. 单个 FIFO 有序队列。
2. 按提示词哈希匹配的录制文件。
3. 本地模型协议兼容 HTTP 服务。
4. VCR 录制与重放。
5. 按请求路由的有序队列。

## 决定

选择选项 5。`tools is None` 进入 `compact` 队列，其他请求进入 `agent` 队列；每条队列内部保持顺序。队列耗尽时抛出 `FakeLLMExhausted`，每次请求深拷贝到 `requests`，测试结束时调用 `assert_consumed()`。

## 为什么否决其他的

单个 FIFO 在只有一条模型调用路径时最简单；当前压缩请求会让它错位。

提示词哈希能捕获请求变化，但提示词仍含动态工具输出，需要大量规范化。提示词结构稳定后可升级。

本地协议服务适合验证 SSE 解析、重试、超时和 socket 故障；阶段 0 只验证循环，不需要传输层。

VCR 能验证真实载荷，但录制需要 API key 和费用，录制文件容易随提示词变化失效。需要跨模型服务协议矩阵时才值得使用。

## 怎么验证

- 强制一次压缩请求，证明 `agent` 队列未被消费；
- 队列缺响应与有多余响应都会使测试失败；
- 每次请求前运行全局消息历史不变量检查；
- 阶段 0 测试不构造真实模型客户端，不访问网络。
