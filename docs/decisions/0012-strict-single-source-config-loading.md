# ADR-0012：配置模型同时持有默认值与未知字段边界

- 日期：2026-08-25
- 状态：已采纳
- 关联：`mini_agent/config.py`、`tests/test_llm_adapters.py`、提交 `7a013e9`

## 背景

原 `Config.from_yaml()` 在根级扁平配置与三层嵌套配置之间手工搬运字段，并用 `.get()` 重复写出模型已经声明的默认值（`git show 7a013e9^:mini_agent/config.py | nl -ba | sed -n '14,192p'`）。改动前把 `max_step`、`retry.max_retry`、`tools.enable_mpc` 和 `tools.mcp.connect_timout` 写入临时 YAML，加载仍然成功，实测分别得到 `50`、`3`、`True` 和 `10.0`；拼错键被丢弃，使用者看到的只是合法默认配置。

问题有两个共同根因：解析函数维护了一份独立字段清单与 18 个默认值，而除 `LLMConfig` 外的 Pydantic 模型默认允许多余字段。只给已知错键增加定向错误不能封住未来拼写错误，也不能消除默认值漂移。

## 选项

1. **保留手工构造并逐层检查键集合**：公开格式不变，改动直接；但字段搬运和默认值仍由解析器与模型分别维护。
2. **新增一套 YAML 输入模型**：让外部输入先完整校验再转换；但当前输入与运行时模型只有根级扁平布局不同，会再复制一套字段与默认值。
3. **复用运行时配置模型并从模型字段派生根级分片**：根级只负责把扁平字段分到 `llm`、`agent`、`tools`，嵌套校验和默认值全部交回现有模型。

## 决定

采用选项 3。全部配置模型继承同一个禁止多余字段的私有基类；`Config.from_yaml()` 从 `LLMConfig.model_fields` 和 `AgentConfig.model_fields` 派生根级允许集合、必填字段与两个分片，最后只调用一次 `Config.model_validate()`（`mini_agent/config.py:14-175`）。合法 YAML 继续使用原扁平布局，运行时仍暴露 `config.llm`、`config.agent` 和 `config.tools`。

旧 `provider` 和 `local_compaction_token_limit` 在通用未知字段检查前保留定向迁移错误。普通未知字段在缺失字段前报告，因此 `api_bsae` 会直接指出未知键，而不是先报告缺少 `api_base`。Pydantic 现有类型转换保持，不在本轮加入 `max_steps`、重试次数或 MCP 超时的数值语义。

## 为什么否决其他的

**否决手工构造加检查**：它只能修复静默忽略，不能消除字段和默认值的双重真源；新增一个合法字段仍要同步修改多个列表和构造参数。若外部格式必须执行逐字段迁移、组合或脱敏，且这些转换不能由运行时模型表达，显式手工映射反而更容易审计。

**否决独立 YAML 输入模型**：当前外部和内部字段语义相同，只在根级布局上不同；复制模型会把本轮要删除的漂移风险换一个位置保留。若将来配置文件需要版本化、别名迁移，或同一运行时模型支持多种明显不同的外部格式，独立输入模型反而是正确边界。

## 怎么验证它是对的

- `.venv/bin/python -m pytest -q tests/test_llm_adapters.py -m 'not external'` 实测 `31 passed in 0.49s`，覆盖根级与三层嵌套未知键、非映射根、程序化构造、全部默认值和全部显式非默认值。
- 临时删除根级未知字段检查，对应回归实测 `1 failed in 0.46s`；临时把共享基类恢复为 `extra="ignore"`，三项嵌套回归实测 `3 failed in 0.46s`。
- 显式排除 `external` 的完整集合实测 `250 passed, 9 deselected in 13.82s`；外部模型、MCP 与网络测试本次未运行。

## 回头看

第一次绿色实现已经消除了默认值复制，但新增测试只检查了默认值和错键；复核指出 `model_fields` 分片将来漏掉合法字段时，这两类测试都不会失败。最终增加了覆盖全部可选字段的非默认值回归，并补齐 API key 的必填与占位错误。没有新增独立输入模型，当前字段单一真源仍由代码和反向验证共同约束。
