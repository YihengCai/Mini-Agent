# ADR-0013：损坏的 Note 存储失败关闭

- 日期：2026-08-25
- 状态：已采纳
- 关联：`mini_agent/tools/note_tool.py`、`tests/test_note_tool.py`、提交 `3013ed2`、`358f561`

## 背景

原 `SessionNoteTool._load_from_file()` 只有“不存在文件返回空列表”的文档承诺，却用 `except Exception: return []` 吞掉读取、解码和 JSON 解析的全部失败（`git show 358f561^:mini_agent/tools/note_tool.py | nl -ba | sed -n '69,114p'`）。改动前把 `{corrupt but important bytes` 写入存储再记录一条 Note，实测结果为 `success=True`、`original_preserved=False`；原字节被只含新 Note 的数组替换。

两个工具还各自解析同一文件，却没有共同结构边界：对 `{}` 或 `null`，读取工具会误报“没有 Note”；对 `["bad"]`，写入工具会追加并覆写，读取工具随后才因元素没有 `.get()` 失败。现有测试用预先创建的 0 字节临时文件模拟首次使用，成功本身依赖同一个吞错行为。

## 选项

1. **把任何无效存储当作空状态**：保持当前表面成功，但会在下一次记录时覆盖无法解析的已有字节。
2. **自动改名隔离原文件并重建**：保留一份备份并继续记录，但工具会未经用户指示移动持久化状态，还需要定义恢复入口和备份生命周期。
3. **只有文件不存在才表示空状态，其他无效状态失败关闭**：读取和写入共享最小结构校验，已有字节在校验成功前绝不进入保存步骤。

## 决定

采用选项 3。模块级 `_load_notes()` 同时服务 `record_note` 与 `recall_notes`：文件不存在返回空列表；已有文件必须是 UTF-8 JSON 数组，且每项必须是对象，否则异常由两个工具现有的外层错误边界转换为失败 `ToolResult`（`mini_agent/tools/note_tool.py:17-27,103-128,173-210`）。测试夹具改用真正不存在的 `tmp_path` 路径，不再把空文件当成新存储。

本轮不改变 Note 字段 schema，不自动修复或移动文件，不注册读取工具，也不处理整文件写入的原子性、并发读改写、容量上限或工作区权限。

## 为什么否决其他的

**否决无效即空状态**：错误被转换成成功后，调用者没有机会阻止下一步覆盖，且新的合法数组会抹掉诊断所需的原始证据。只有该文件明确是可丢弃缓存、上层已持有权威副本时，这种自愈才合理。

**否决自动隔离重建**：保留备份比直接覆盖安全，但“备份在哪里、何时删除、怎样恢复、并发调用谁负责”都会成为新的持久化 contract。若未来提供显式恢复命令、可审计的备份命名和保留策略，隔离后重建反而可以成为用户选择。

## 怎么验证它是对的

- `.venv/bin/python -m pytest -q tests/test_note_tool.py tests/test_session_integration.py -m 'not external'` 实测 `11 passed in 0.43s`。
- 回归分别写入损坏 JSON、对象根和含非对象元素的数组，同时调用读取与写入工具；两者必须失败，存储字节逐字不变。
- 临时恢复读取/解析的宽泛异常降级后，损坏 JSON 回归实测 `1 failed in 0.46s`。
- 显式排除 `external` 的完整集合实测 `253 passed, 9 deselected in 13.89s`；外部模型、MCP 与网络测试本次未运行。

## 回头看

实现前复核现有测试时发现，`NamedTemporaryFile` 预先创建的空文件并不等价于工具承诺的“不存在文件”；先将三项测试改成 `tmp_path`，在行为不变时单独提交，再加入失败回归和最小实现。结构探针进一步证明两个独立解析器对 `{}`、`null` 和 `["bad"]` 给出不一致结果，因此最终共享读取与结构校验，而不是只删除一个 `except`。
