# Skill 发现的注册表快照

> 状态：已实现。状态持有与发现位于 `mini_agent/tools/skill_loader.py:47-58,194-265`，离线回归位于 `tests/test_skill_loader.py:97-157`；取舍见 [ADR-0020](../decisions/0020-transactional-skill-discovery.md)。

## 问题证据

旧发现流程扫描时直接更新长期注册表，不删除已经消失的条目，并让后扫描的同名文件静默覆盖前者（`git show 9c15477^:mini_agent/tools/skill_loader.py | nl -ba | sed -n '194,214p'`）。返回的发现列表因此可能与提示词和 `GetSkillTool` 使用的名称索引不一致。

## 本轮不变量

1. 每次发现先在局部状态中完成，成功后才一次发布注册表。
2. 成功重扫只包含当前仍可发现且成功解析的 Skill，已删除条目不能驻留。
3. 扫描路径稳定排序，返回列表、元数据顺序和重名诊断可复现。
4. 同一次扫描内名称必须唯一；冲突错误包含两个来源路径。
5. 重名导致整次扫描失败，上一份成功注册表保持不变。
6. 不存在的目录和没有有效文件的目录发布空注册表。

## 不在范围

不改变单项 YAML frontmatter（文件头元数据）的现有最小校验、内容路径改写、`allowed-tools` 执行、CLI 组装、动态监视、多个来源的覆盖层次、信任级别或权限。

## 离线验证

- 首次发现两个 Skill，删除其中一个后重扫只保留仍存在的一项；
- 先发布稳定条目，再加入两个重名来源，重扫明确失败并保留旧快照；
- 重名诊断同时包含按路径排序的两个 `SKILL.md`；
- 退化为累加更新或移除重名拒绝时，对应回归转红。
