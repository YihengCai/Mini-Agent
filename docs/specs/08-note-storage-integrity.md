# Note 存储的失败关闭边界

> 状态：已实现。共享读取与两个工具的错误边界位于 `mini_agent/tools/note_tool.py:17-210`；离线回归位于 `tests/test_note_tool.py:1-90`；取舍见 [ADR-0013](../decisions/0013-fail-closed-note-storage.md)。

## 问题证据

原写入工具把任何读取或 JSON 解析错误都当成空 Note 数组，再整文件覆写。损坏字节探针实测写入返回成功且原始内容消失；对象根和含非对象元素的数组还会让读写工具给出互相矛盾的结果。

## 本轮不变量

1. 只有文件不存在表示尚无 Note；合法的空数组才表示已有空存储。
2. 已有文件必须是 UTF-8 JSON 数组且每项为对象；读写工具使用同一个解析与结构校验入口。
3. 读取、解码、解析或结构校验失败时，读写工具都返回失败。
4. 写入只有在完整读取与校验成功后才能开始；因此无效存储的原字节保持不变。
5. 首次记录、连续记录、分类读取和跨工具实例持久化的既有行为保持。

## 不在范围

不改变 Note 对象字段，不自动修复、备份或移动损坏文件，不处理原子写、并发更新、容量预算、权限，也不注册当前缺失的 `recall_notes` CLI 工具。

## 离线验证

- 不存在文件可以成功写入并由新工具实例读取；
- 损坏 JSON、对象根和含非对象元素的数组会让两个工具失败；
- 每个无效输入在调用前后使用 `read_bytes()` 比较，必须逐字一致；
- 恢复宽泛异常降级会使损坏 JSON 回归转红。
