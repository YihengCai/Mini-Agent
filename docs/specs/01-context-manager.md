# 上下文管理

> 状态：待事件层与测试框架完成后实现。提示词缓存由端点能力探测结果单独决定。

## 要解决的问题

当前 `_summarize_messages()`（`mini_agent/agent.py:153-232`）原地覆写 `self.messages`：它删除工具调用结构，把摘要再次作为 `role="user"` 参与下一次压缩；`_create_summary()`（`mini_agent/agent.py:257-292`）把没有大小限制的工具结果送进摘要请求，失败时返回原文，因此压缩可能让上下文变大。复现见 [P-002](../PITFALLS.md)。

## 数据模型

`self.messages` 变成仅追加的 `raw_log`；模型请求使用派生视图：

```text
raw_log + ContextState
  -> 淘汰工具结果
  -> 单一移动摘要
  -> 请求视图
```

`build_view(raw_log, state) -> list[Message]` 必须是确定性的纯函数。`raw_log` 是事实记录，压缩状态只决定当前请求包含什么。

## 两阶段压缩

### 1. 淘汰工具结果

按 `tool_call_id` 记录被淘汰的结果，只修改工具消息的 `content`，保留 `role`、`name` 和 ID。占位内容必须非空，并说明工具、淘汰原因，以及需要原文时应重新调用工具。

候选项只能来自已经闭合、且位于保护窗口之外的工具调用组。不要按原始下标持久化淘汰状态；中断或回退会移动下标。

### 2. 单一摘要窗口

只保留一份 `SummaryRecord(text, upto_index)`，`upto_index` 单调前进。边界不能切入 assistant 工具调用及其全部工具结果构成的原子组；找不到安全边界就拒绝生成摘要，让淘汰继续工作或明确返回上下文上限错误。

摘要输入必须逐条限制，并有总量上限；网络失败时使用确定性的结构化降级结果，不能返回原始全文。摘要输出必须严格小于被替换的输入。

## Trigger

以最近一次真实的 `usage.prompt_tokens` 为锚点，只用本地 tokenizer 估算锚点之后新增的消息。工具数据结构不在 `self.messages` 中，因此不能把本地 token 总量估算当作真实 `usage`。

使用高低水位与滞后区间，避免每一步都压缩；阈值必须由当前端点的上下文上限与探测结果决定，文档不预填数字。

## 提示词缓存的能力前置条件

先运行[能力矩阵](../PROVIDER_CAPABILITIES.md)中的 C1–C3：

- C1/C2 不成立：不实现 `cache_control` 断点，上下文管理器只保证正确性与 token 预算；
- C1/C2 成立：另开 ADR，验证工具与 system 消息的顺序、断点位置和压缩频率；
- C3 决定触发条件怎样组合 `input_tokens`、`cache_read_input_tokens` 与 `cache_creation_input_tokens`。

不保留不起作用的缓存实现。没有端点证据的代码会把 vendor 假设扩散进核心模块。

## 文件状态边界

本模块不维护 FileLedger。读取后文件变化检查、写前读取和编辑后磁盘哈希属于[事务式编辑](04-transactional-edit.md)；上下文管理器只负责消息视图。只有具体失败案例证明压缩导致模型丢失关键文件状态，才单独设计可重建的工作集摘要。

## 离线验证

`tests/test_context_invariants.py` 使用固定随机种子的生成器，覆盖串行与并行工具调用组：

- 任意有效状态生成的视图都没有未配对记录；
- 同一 `(raw_log, state)` 两次输出逐字节一致；
- 淘汰操作不删除消息骨架；
- 摘要边界不切入工具调用组；
- 摘要失败时输出仍小于输入；
- 找不到安全边界时明确拒绝，而不是生成无效请求。

`scripts/ctx_bench.py` 只做离线对话重放，报告请求 token 峰值、累计请求 token、摘要调用次数和未配对记录数。缓存指标只有 C1–C3 探测通过后才加入。

## 不在范围内

跨会话摘要、语义排序、重新载入被淘汰结果、subagent 隔离、文件账本、vendor 专用上下文管理。
