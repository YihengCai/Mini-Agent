# 严格配置解析与默认值单一真源

> 状态：已实现。配置模型与 YAML 分片位于 `mini_agent/config.py:14-175`；离线回归位于 `tests/test_llm_adapters.py:48-255`；取舍见 [ADR-0012](../decisions/0012-strict-single-source-config-loading.md)。

## 问题证据

原解析器逐层使用 `.get()`，把 Pydantic 模型的 18 个默认值再声明一次，同时静默忽略根级、重试、工具和 MCP 的未知键。改动前探针中的四个拼错字段分别回落为 `50`、`3`、`True` 和 `10.0`，加载没有报错。

## 本轮不变量

1. YAML 继续使用根级模型字段、agent 字段和嵌套 `tools` 的现有布局；运行时对象仍分为 `llm`、`agent`、`tools`。
2. 任一配置模型遇到未知字段都拒绝构造；根级错误列出未知键，嵌套错误保留 Pydantic 字段路径。
3. 必填模型字段从 `LLMConfig.model_fields` 派生；可选字段缺省时只由模型默认值补全。
4. 解析器只负责验证根是映射、保留两个旧字段的定向错误、检查 API key，并把根级字段分片后一次完成模型校验。
5. 全部合法显式字段逐值保留，不能因为分片重构而静默丢失。

## 不在范围

不改变 Pydantic 的现有类型转换，不新增数值约束，不改变配置搜索优先级，也不解决系统提示词与 MCP 配置可能来自另一目录的问题。

## 离线验证

- 根级 `max_step`、`retry.max_retry`、`tools.enable_mpc` 和 `tools.mcp.connect_timout` 均失败并指出原键；
- 非映射根、缺少每个必填字段、占位 API key、旧字段和无效 adapter 保持明确失败；
- 最小配置精确得到模型声明的全部默认值，完整非默认配置精确透传每个字段；
- 直接构造任一配置模型也不能携带未知字段。
