# 事务性编辑 + 诊断回灌

> 状态：待上下文管理后实现；前置的唯一匹配守卫可以先独立落地。

## 要解决的问题

`EditTool` 描述承诺 `old_str` 唯一，否则失败；实现却在 `mini_agent/tools/file_tools.py:280` 调用不带 `count` 的 `content.replace()`，会替换全部匹配，空字符串还会把文件打散。复现见 [P-001](../PITFALLS.md)。成功回执也没有替换数、diff 或写后校验，调用方无法发现静默误改。

## 分阶段实现

### 1. 先修契约

- `old_str == ""` 直接失败；
- `content.count(old_str) != 1` 直接失败并返回实际匹配数；
- 成功返回替换数和受影响行区间；
- 写前后编码与换行保持逐字节策略，不偷偷归一化。

这一步是 bug 修复，不等待完整编辑引擎。

### 2. PatchSet 的匹配与验证

多 hunk 编辑全部对原始缓冲区匹配，先得到不重叠的 byte/character range，再按偏移降序应用。匹配阶梯只能从严格到保守：

1. 精确且唯一；
2. 去尾空白后唯一，并能映射回原始范围；
3. 明确受限的缩进归一化，仍需唯一；
4. 失败，请模型重读。

任何回退只要产生多义性就停止。Python 缩进改变语义，不能把“忽略全部空白”当容错。

### 3. 陈旧性

读取时记录 `path -> (mtime_ns, size, sha256)`；编辑前重新计算。任一字段变化都拒绝旧 patch，并要求重读。`bash` 可以绕过文件工具修改文件，因此检查必须面对磁盘状态，不能只看工具历史。

### 4. 写入边界

先在内存验证整个 PatchSet，再为每个目标写同目录临时文件并 `os.replace()`，得到单文件原子替换。多个文件在进程崩溃时仍不具备真正的跨文件原子性；在 checkpoint 落地前，文档只能承诺“全量预验证 + 单文件原子写”，不能宣称事务数据库式回滚。

### 5. 诊断回灌

写后只运行仓库已有、可离线执行的检查器；优先语法检查，再跑配置明确允许的 lint。只回灌与本次 diff 行区间相交的诊断，并保留工具名、文件和行号。全仓库历史错误不进入 agent 上下文。

## 可失败工件

`tests/test_edit_engine.py` 至少覆盖：

- 空字符串、多匹配、零匹配都不写磁盘；
- 多 hunk 偏移变化后仍修改正确范围；
- hunk 重叠时整个 PatchSet 失败；
- 读取后外部改写文件会触发 stale；
- 保留 CRLF 与无尾换行文件；
- 临时文件准备失败时原文件均未改；
- 诊断过滤只返回相交行。
