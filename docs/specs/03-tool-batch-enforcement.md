# 工具注册与批次执行强制点

> 状态：已实现。冻结注册、调用标识符账本与模型工具执行位于 `mini_agent/core/tool_execution.py:31-193`；agent loop 的唯一挂钩与成组提交位于 `mini_agent/core/agent.py:99-102,314-431`；离线回归位于 `tests/test_tool_execution.py:150-719`。

## 问题证据

Session 以字典推导注册工具，同名工具由列表后项静默覆盖；每个 Step 又从原始可变 Tool 对象读取名称、说明和参数，所以模型可见定义可能与注册键分叉。模型响应的整批工具调用没有生产预检：空、同批重复或历史重复调用标识符可能在副作用执行并写入历史后，才由 `tests/llm_test_double.py:30-70` 的下一次请求检查发现。

## 本轮不变量

1. 工具名称在 Session 构造时必须非空且唯一；名称、说明与参数定义只读取一次，后续模型定义和调度都使用同一冻结注册项。
2. 每个模型返回的工具批次在首个 `ToolStarted` 与首个副作用前，验证调用类型、非空标识符、批内重复及本 Session 已认领标识符；结构错误不提交 assistant/tool 消息，也不认领其中任何标识符。
3. 合法批次按模型顺序串行执行。未知工具、工具抛出的普通异常和非法返回各自产生一个失败 `ToolResult`，不阻止其余调用。
4. `_AgentLoop` 只把完整批次交给一个执行入口一次；执行入口负责所有由模型响应触发的 `Tool.execute()`、结果规范化、工具事件与结果消息构造。`AgentSession.tools` 仅为可信宿主保留只读注册视图，不构成模型调用路径或安全边界。
5. assistant 工具调用与全部结果仍成组写入；观察者失败后完成当前批次，中断仍只在完整 Step 边界生效。
6. 完整预检后，每个调用在自身 `ToolStarted` 与副作用前才认领标识符；若 `asyncio.CancelledError` 逃逸，已启动调用保持认领，未启动调用可在后续 Turn 重试。这是 executor 内部的保守 at-most-once（最多执行一次）账本，不是模型可见历史中的事实；当前取消仍不生成 `StepFinished` 或 `TurnOutcome`。传给工具的嵌套参数使用独立快照，工具不能反向修改事件或历史中的调用结构。

结构错误以 `TurnError(kind="tool_protocol_error")` 返回，区别于模型传输失败、工具自身失败和 core 内部错误。

## 不在范围

不做 JSON Schema 参数校验、并行工具、自动重试、权限与沙箱、输出预算、工具取消恢复或回滚、MCP 生命周期、后台 shell 管理或跨进程恢复。

## 离线验证

- 重名与空名注册在 Session 创建时失败；注册后修改 Tool 元数据不会改变模型定义或调度键。
- 同批、跨 Step 和跨 Turn 重复调用标识符在零新增副作用前失败；非法批次不产生工具事件或半配对历史。
- 成功、未知工具、抛异常和非法返回组成的同批调用各产生一个同序结果。
- 阻塞批次中途检查不到 assistant/tool 半成品；观察者失败时其余调用仍执行并一次性提交；agent loop 只调用一次整批入口。
- 阻塞首个调用时请求中断，不会并发启动后项，且后项仍按序完成；取消首项只认领已启动标识符，未启动后项可在下一 Turn 重试。
- 工具修改嵌套参数不会污染 `ToolStarted`、`ToolFinished` 或 assistant 历史。
