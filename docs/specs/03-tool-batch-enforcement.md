# 工具注册与批次执行强制点

> 状态：已实现。冻结注册、批次预检与模型工具执行位于 `mini_agent/core/tool_execution.py:32-184`；agent loop 的模型返回值接纳、唯一挂钩与成组提交位于 `mini_agent/core/agent.py:103-106,346-431`；离线回归位于 `tests/test_tool_execution.py`。

## 问题证据

Session 原来以字典推导注册工具，同名工具由列表后项静默覆盖；每个 Step 又从原始可变 Tool 对象读取名称、说明和参数，所以模型可见定义可能与注册键分叉。模型响应的整批工具调用也没有生产预检：非法类型、空标识符或同批重复可能在副作用后才被测试替身发现。

## 本轮不变量

1. 工具名称在 Session 构造时必须非空且唯一；名称、说明与参数定义只读取一次，后续模型定义和调度都使用同一冻结注册项。
2. `ModelClient.generate()` 返回后，agent loop 立即深拷贝整个 `LLMResponse`，再发出响应事件、检查工具批次或构造 assistant 消息；客户端保留的返回对象不再能改写已接纳状态。
3. 每个模型返回的工具批次在首个 `ToolStarted` 与首个副作用前验证调用类型、非空标识符和批内重复；结构错误不提交 assistant/tool 消息。
4. 合法批次按模型顺序串行执行。合法 `ToolResult` 在接纳处立即深拷贝，工具保留的返回别名不能改写事件或历史；未知工具、工具抛出的普通异常和非法返回各自产生一个失败 `ToolResult`，不阻止其余调用。
5. `_AgentLoop` 只把完整批次交给一个执行入口一次；执行入口负责所有由模型响应触发的 `Tool.execute()`、结果规范化、工具事件与结果消息构造。`AgentSession.tools` 仅为可信宿主保留只读注册视图，不构成模型调用路径或安全边界。
6. assistant 工具调用与全部结果仍成组写入；观察者失败后完成当前批次，中断仍只在完整 Step 边界生效。
7. 调用标识符只关联一个未完成批次中的调用与结果；完成配对后，后续 Step 或 Turn 可以复用相同值。执行器不持有隐藏账本，也不宣称提供 at-most-once（最多执行一次）。传给工具的嵌套参数使用独立快照，工具不能反向修改事件或历史中的调用结构。

结构错误以 `TurnError(kind="tool_protocol_error")` 返回，区别于模型传输失败、工具自身失败和 core 内部错误。

## 不在范围

不做 JSON Schema 参数校验、并行工具、自动重试、权限与沙箱、工具取消恢复或回滚、MCP 生命周期、后台 shell 管理或跨进程恢复。模型可见输出预算后来由 [模型可见工具输出预算](05-tool-output-budget.md) 在同一批次执行器投影边界实现。

## 离线验证

- 重名与空名注册在 Session 创建时失败；注册后修改 Tool 元数据不会改变模型定义或调度键。
- 同批重复调用标识符在零新增副作用前失败；已完成批次的标识符可跨 Step 和 Turn 复用并正常执行。
- 成功、未知工具、抛异常和非法返回组成的同批调用各产生一个同序结果。
- 阻塞批次中途检查不到 assistant/tool 半成品；观察者失败时其余调用仍执行并一次性提交；agent loop 只调用一次整批入口。
- 阻塞首个调用时请求中断，不会并发启动后项，且后项仍按序完成。
- 工具修改嵌套参数不会污染 `ToolStarted`、`ToolFinished` 或 assistant 历史。
- 工具保留返回结果并在 `ToolFinished` 后修改别名，不会污染事件快照、模型消息或 Session 历史。
- 模型客户端在首项工具阻塞期间修改自己保留的响应对象，不会绕过重复标识符预检，也不会污染后续副作用、assistant 历史或工具结果标识符。
