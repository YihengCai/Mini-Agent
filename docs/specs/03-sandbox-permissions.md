# 沙箱 + 结构化权限

> 状态：待事件层完成后实现。每个平台必须独立通过真实拒绝测试，不能靠“检测到可执行文件”宣称支持。

## 要解决的问题

`BashTool` 把模型生成的字符串直接交给 `asyncio.create_subprocess_shell()`（`mini_agent/tools/bash_tool.py:391-396`）；文件工具接受工作区外的绝对路径和 `..`。权限判定也不能建立在 `shlex.split()` 后的第一个 token 上，反例见 [P-006](../PITFALLS.md)。

## 信任边界

权限解析器回答“是否自动执行、是否询问用户”；操作系统沙箱回答“即使判定错了，进程能影响哪里”。解析器不是安全边界，沙箱也不替代用户授权。

只有调用确实运行在同时通过正反例探测的沙箱内，`ASK` 才能降级为 `ALLOW`；`DENY` 永不降级。`NoSandbox` 下所有 `ASK` 都必须由用户决定。

## 平台范围

当前开发环境先实现并验证 macOS seatbelt：

- 工作区与专用临时目录可写；
- 工作区外写入被拒；
- 出站网络被拒；
- 配置路径通过参数绑定，不拼接用户路径；
- 启动探测同时证明“内部可写”和“外部被拒”。

Linux bwrap 保留同一接口和设计说明，但在 Linux 环境跑通相同探测与测试矩阵前，不进入 README 的支持列表。其他平台使用 `NoSandbox`，不得静默放宽权限。

## 权限解析与策略

解析过程保留原始字符串中的引号与展开信息，再识别组合命令、重定向和包装命令：

- 解析失败 → 默认拒绝；
- `;`、`&&`、`||`、管道和子 shell 分段，采用最严格的判定；
- 未解析变量、命令替换、heredoc、解释器载荷至少为 `ASK`，高风险形式可直接 `DENY`；
- 规则匹配基于 `(argv0, subcommand, flags, resolved paths)`，不是字符串前缀；
- 未命中规则默认 `ASK`；
- 会话授权使用规范化结构作 key，不使用原始命令文本。

权限界面通过事件层收发请求与响应，不在工具内直接调用 `input()`；否则会与现有 Esc 输入线程竞争 stdin。

## 文件工具的工作区边界

Read/Write/Edit 的目标先 `.resolve()`，再用 `Path.is_relative_to(workspace)` 判断。符号链接逃逸、绝对路径和不存在的末级路径都要有明确策略。检查发生在真正打开文件之前。

防护包装器集中在工作区工具的统一构造点，确保 CLI 与 ACP 得到相同的 `GuardedTool`；测试还要证明所有执行路径都经过防护。

## 验证

`tests/test_permission_corpus.py`：

- 对抗命令集在 `NoSandbox` 下验证原始 `ALLOW/ASK/DENY + reason`；
- 同一命令集在 `FakeActiveSandbox` 下验证 `ASK -> ALLOW`、`DENY` 不变；
- 解析失败时不执行；
- CLI 与 ACP 构造的修改类工具都被防护包装器包裹；
- 工作区边界检查覆盖绝对路径、`..`、符号链接和相似前缀目录。

`scripts/sandbox_probe.py` 在真实 seatbelt 下打印允许/拒绝矩阵，最后固定打印 `NOT PREVENTED`：读取工作区外的密钥、工作区内的破坏性操作、MCP 副作用、内核或沙箱配置漏洞。

## 不在范围内

Linux 支持声明、Windows 访问令牌沙箱、容器编排、完整 shell AST、持久化始终允许规则、针对恶意模型的安全声明。
