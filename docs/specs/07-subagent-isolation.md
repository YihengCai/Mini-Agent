# subagent 上下文隔离

> 状态：后期设计，未实现。依赖：事件层、上下文管理器、权限控制和预算统计。

## 要研究的问题

subagent 的价值不是“再开一段对话”，而是限制探索过程的记录进入父级上下文。父 agent 只能收到有限且可验证的结果；subagent 对话记录不直接追加到父级消息列表。

## 不变量

- 每次委派只让父级上下文增加一个 assistant 工具调用和一个有限的工具结果；
- subagent 没有修改类工具、`task` 工具或默认 MCP 权限；
- 唯一正常出口是结构化的 `submit_report`；
- 报告中的路径、行号和引用在返回父 agent 前对工作区验证；
- 步数、输入 token、运行时间分别设置上限，任一耗尽都只允许一个有限的恢复轮次；
- 父级取消操作单向传递给子级，子级失败不能取消父级；
- 不允许递归创建 subagent；
- 权限请求默认拒绝，不在父级 UI 中静默批准。

## 候选设计

父 agent 通过 `task` 工具创建一个共享 LLM 客户端、但消息列表独立的只读 agent。subagent 只获得 Read/Glob/Grep 与权限层批准的只读工具；结束时调用 `submit_report` 返回问题、答案、证据、检查过的文件和未解决事项。

报告长度使用确定性的截断策略，不调用第二次 LLM 摘要。预算耗尽时只保留 `submit_report`，允许返回一次不完整报告；仍失败则返回明确的错误 `ToolResult`。

## 进入条件

1. 父级循环已有事件流和结构化结束原因；
2. 上下文管理器已实现，可以测量父级上下文峰值；
3. 权限引擎能构造只读工具子集；
4. shell 注册表与取消路径不再依赖进程级隐式状态；
5. FakeLLM 支持第三类路由，且有需求证明两条队列不够。

## 验证

`tests/test_subagent_isolation.py` 必须证明：

- subagent 读取含唯一标记的大型测试样例后，标记不出现在父级消息中；
- 父级消息只增加一个已经闭合的工具调用组；
- 修改类工具、MCP 和递归任务不在子级工具列表中；
- 捏造的路径或引用会被标记，并降低置信度；
- 预算耗尽只增加一次恢复调用；
- 取消与超时不遗留子进程或后台 shell。

任务级修改前后评测等实现完成后再设计；不能用旧压缩器作为 baseline 提前写预测。
