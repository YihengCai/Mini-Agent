# 事务式编辑 + 诊断

> 状态：待上下文管理后实现；唯一匹配防护可以先独立落地。

## 要解决的问题

`EditTool` contract 要求 `old_str` 唯一，否则失败；实现在 `mini_agent/tools/file_tools.py:280` 调用不限制次数的 `content.replace()`，会替换所有匹配，空字符串还会破坏文件。复现见 [P-001](../PITFALLS.md)。成功结果也没有替换次数、代码差异或写后校验，调用方无法发现静默修改。

## 实现阶段

### 1. 修复工具 contract

- `old_str == ""` 直接失败；
- `content.count(old_str) != 1` 直接失败并返回实际匹配数；
- 成功结果返回替换次数和受影响的行区间；
- 编码与换行符遵守保留原始字节的策略，不做静默规范化。

这是独立问题修复，不等待完整编辑引擎。

### 2. PatchSet 匹配与预检

所有修改块都对原始缓冲区匹配，先得到互不重叠的字节或字符区间，再按偏移量从后向前应用。降级匹配只能从严格走向保守：

1. 精确且唯一；
2. 去掉行尾空白后仍然唯一，并能映射回原始区间；
3. 有限规范化缩进后仍然唯一；
4. 失败，要求模型重新读取。

任何降级匹配产生歧义就停止。Python 缩进会改变语义，不能使用忽略全部空白的匹配。

### 3. 文件变化检查

读取时记录 `path -> (mtime_ns, size, sha256)`；编辑前重新计算。任一字段变化都拒绝基于旧内容的补丁，并要求重新读取。`bash` 可以绕过文件工具修改文件，因此检查必须读取磁盘状态，不能只看工具调用历史。

### 4. 写入边界

先在内存中预检整个 PatchSet，再为每个目标写入同目录临时文件并调用 `os.replace()`，提供单文件原子替换。进程崩溃时仍没有跨文件原子性；检查点完成前只承诺“全部文件预检 + 单文件原子写入”，不宣称具备数据库事务回滚能力。

### 5. 诊断

写入后只运行仓库已有且可离线执行的检查器；先做语法检查，再运行配置明确允许的 lint。只返回与本次代码差异行区间相交的诊断，并保留工具名、文件和行号。仓库中原有的全局错误不进入 agent 上下文。

## 验证

`tests/test_edit_engine.py` 至少覆盖：

- 空字符串、多处匹配、零匹配都不写磁盘；
- 多段修改导致偏移量变化后仍修改正确区间；
- 修改块重叠时整个 PatchSet 失败；
- 读取后发生的外部修改会触发拒绝；
- 保留 CRLF 与无尾换行文件；
- 临时文件准备失败时原始文件均未修改；
- 诊断过滤器只返回相交的行。

## 不在范围内

AST 重写、LSP、跨进程锁、跨文件崩溃原子性、自动检查点回滚、语义模糊匹配。
