# LLM 测试替身与模型请求结构检查

> 状态：当前实现规格，尚未开始编码。这里只记录已经由 baseline 代码证明的问题和第一步边界；具体类名、文件拆分与异常名由实现决定。

## 问题证据

现有 agent loop 测试会访问真实 API，部分测试还以返回布尔值代替断言，因此不能提供快速、便宜、稳定的回归反馈，见 [`UPSTREAM_AUDIT.md`](../UPSTREAM_AUDIT.md)。

`Agent.run()` 会调用 `llm.generate(messages, tools=...)`，`Agent._create_summary()` 也会调用同一方法但传入 `tools=None`（`mini_agent/agent.py:275-283`）。测试替身必须能区分主循环调用与摘要调用，避免两种响应互相消费。

## 本轮范围

- 实现一个可注入的、脚本化的 LLM 测试替身；
- 按调用用途分别提供有序响应；
- 记录收到的请求，意外调用和未消费响应都让测试失败；
- 在模型请求边界检查工具调用与工具结果的配对结构；
- 用它驱动真实 agent loop 的离线回归测试。

不在本轮范围：本地 HTTP/SSE 假服务、真实端点评测、录制回放、事件层、任务基准测试。

## 需要通过测试确定的行为

1. 主循环和摘要调用不会消费彼此的预设响应；
2. 预设响应不足或测试结束时仍有剩余响应都会失败；
3. 测试可以断言模型实际收到的消息和工具定义；
4. 工具调用缺少结果、结果引用未知调用或标识符重复时，请求在离线边界失败；
5. 未知工具、工具异常、达到最大步数和正常结束能被区分。

具体接口只有在第一条能够暴露当前问题的回归测试写出后才确定。如果单纯依据 `tools is None` 路由不能覆盖真实调用图，再记录新的取舍。
